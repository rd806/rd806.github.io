我从2025年2月初开始学习搭建MC服务器，到现在也学到了不少知识。以下是我的开服历程，若能对各位有所帮助，实在是我的荣幸。

服务端搭建

常见的服务端

目前MC服务端主要包括：原版、插件端、模组端和混合端四类。

类别 特点
原版 就和MC原版一样，没有特殊功能
插件端 能加插件，不能加模组
模组端 能加模组，不能加插件
混合端 既能加模组，也能加插件

似乎混合端功能更强大，但实际上它的兼容性更差，所以如果想开整合包服务器的话最好还是用模组端。

由于我目前没找到合适的模组代替插件，因此只能用混合端了。

以下是常见的服务端：

服务端 类别 支持
Spigot 插件端 全版本
Paper 插件端 全版本
Forge/Fabric/NeoForge 模组端 全版本
Catserver（猫端） 混合端 1.12.2/1.16.5/1.18.2
Mohist（墨端） 混合端 主要为1.20.1

安装 Java 环境

Java环境是MC服务器必备的运行环境。Java有多个版本，不同的MC服务端对应不同的Java。

MC版本 支持
1.12 - 1.16 Java 8
1.17 - 1.20 Java 17
1.21 以上 Java 21

Java可从Oracle官网下载（最新版需要注册账号才可下载）。如果不在意，也可从镜像站例如Adoptium下载。

使用.exe或.msi文件安装的Java一般自动配置好了环境变量，如果使用.zip安装Java则需手动配置。

服务端启动流程

以Windows系统为例：

  1. 从网络上下载对应的服务端，通常是一个.jar文件。
  2. 新建一个文件夹，将服务端核心放在文件夹内。
  3. 在文件夹内新建一个文本文档，文档内输入java -jar 你的服务端核心名.jar，保存后将文件扩展名改为.bat。
  4. 双击.bat文件，服务端将会运行并且在终端实时输出。这时通常会出现是否同意eula协议，此时须在文件夹内找到eula开头的文件，将其中的false改为true。
  5. 再次启动.bat文件，服务端开启成功。

若为Linux系统，则需要将启动文件改为.sh文件，同时使用chmod +x xxx.sh赋予执行权限。

网络配置

搭建服务器最重要的是配置好网络，核心是确定服务器的IP地址和端口号。

局域网联机

局域网联机最简单，只需知道服务器运行的主机的IP地址即可。

Windows平台：WIN + R 打开cmd，输入ipconfig，查看Wifi（无线连接）或以太网（有线连接）下的IP地址。

Linux平台：命令行输入 ip a 。

通俗来说，通过同一个Wifi相连的设备都处于同一个局域网下。连接在同一个局域网下的设备，它们的设备IP地址仅最后一位不同。在同一个局域网下的设备可通过IP地址互相连接。

若路由器开启了AP隔离（大部分校园网等），则此方法可能失效。

内网穿透

请在网络上自行查找相关内容。

内网穿透是通过特定技术，将你的内网（如局域网）地址经服务器映射到公网上的过程。此时一个公网IP地址，如：frp-xxx.com:xxxxx就等同于你的局域网地址192.168.x.x。

IPv6连接

这是目前成本最低，效果最好的连接方式。

首先必须确保你和你的伙伴都有IPv6访问，然后查看IP地址，这时应该可以看到一串240e:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx（必须为240e开头，这样才是公网IPv6），这时[IPV6地址]:端口号的形式就是服务器的IP地址。

目前IP技术分为IPv4和IPv6两种。IPv4地址为12个十进制数，每3个数字用.隔开；IPv6地址为28个16进制数，每4个数字用:隔开。由此可见，IPv6地址比IPv4多得多，所以每个IPv6地址都可以作为公网使用。

如果你拥有一个域名，则可以给该域名添加一个AAAA记录（如www.yourdomain.com）绑定到公网IPv6，再添加一个CNAME记录（如mc.yourdomain.com）指向该AAAA记录。这样就可以通过mc.yourdomain.com:port连接到服务器。

如果想去除端口号，则再添加一个SRV记录：

设置 参数
名称 _minecraft._tcp.mc
权重 5（满足取值要求即可）
端口 服务器的端口
目标 www.yourdomain.com

这样就可以通过mc.yourdomain.com直接连接。

#!/bin/bash
set -e

# 1. 如果 MySQL 没装，就装（可选）
# sudo apt update && sudo apt install -y mysql-server

# 2. 确保 MySQL 服务已启动
sudo service mysql start
# sudo systemctl is-active --quiet mysql || { echo "MySQL 启动失败"; exit 1; }

# 3. 等待 3306 真正响应
until nc -z 127.0.0.1 3306; do
  echo "等待 MySQL 端口 3306 …"
  sleep 1
done

# 4. 启动 MC（stop正常退出，崩溃自动重启）
cd {"服务器所在目录"}
while true; do
    java -Xms4G -Xmx8G -jar mohist-1.20.1.jar
    EXIT_CODE=$?
    
    # 退出码 0 = 正常停止 (stop命令)
    if [ $EXIT_CODE -eq 0 ]; then
        echo "服务器正常关闭，退出脚本"
        break
    fi
    
    echo "服务器异常终止 (退出码: $EXIT_CODE)，5秒后自动重启..."
    sleep 5
done

在java -jar 你的服务端核心名.jar中，可在-jar之后加上-XmsAG -XmxBG表示给服务器至少分配A个G的内存，至多分配B个G的内存。

特别的，java可以替换为具体的Java/bin路径。若未指明，默认为环境变量中的Java。

服务器引入MySQL

对于多个服务器，如果想不同服务器之间共享玩家数据（如权限、经验等），可以使用MySQL数据库。

下面以服务端插件PowerRanks为例进行说明：

  1. 打开PowerRanks的配置文件，找到关于数据来源的配置。 将type改为mysql，并配置好端口、用户名和密码。这样在启动时，插件会自动从127.0.0.1:3306端口的root用户读入数据。

这是一个 IPv6 连接，状态是ESTAB（已建立），但Send-Q是367（第二列数字）。

正常情况下Send-Q应该是0。367表示TCP发送缓冲区里有367字节数据，对端一直没有确认。表明你的服务器在等对方说"我收到了"，但对方没回应。

目标地址2606:50c0:8003::154解析后是 GitHub 的 IPv6 地址（CDN 节点）。说明Alex’s Caves 正在从 GitHub 下载不兼容列表。但是有时 GitHub 的 IPv6 节点响应正常，有时这个节点丢包或延迟高，导致启动服务器时会概率地发生“卡住”的现象，而5分钟正好是HTTP响应超时的用时。

所以为什么日志中没有显示呢？我也不知道……

一劳永逸的解决方法是修改host文件，

1

sudo nano /etc/hosts

添加如下内容：

1
2

127.0.0.1 raw.githubusercontent.com
127.0.0.1 api.github.com

通过将 GitHub 的域名指向本地，模组的连接请求会立刻失败，从而瞬间跳过。

或者想办法与Github建立稳定连接，我们将其作为习题留给读者思考。

保存文件后，重新启动服务器即可。
